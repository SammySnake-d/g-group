#17 我: 解释一下什么是缓存
#18 小克: 缓存(Cache)就是把常用的数据先放在一个读得更快的地方。下次再要用时直接从这里拿,不用每次都去慢的地方重新取或重新算。

打个比方:常用的书摆在书桌上(缓存),不用每次都跑去书架或图书馆(原始数据源)找。

常见的几种:
- CPU 缓存:L1、L2、L3,放的是 CPU 马上要用的内存数据,比内存快很多。
- 浏览器缓存:把网页里的图片、JS、CSS 存在本地,第二次打开会快。
- 应用缓存:比如 Redis、Memcached,把数据库查询结果放在内存里,减轻数据库的压力。
- CDN:把静态资源放到离用户近的节点上。

几个关键概念:
- 命中(hit)和未命中(miss):要的数据在缓存里就是命中,不在就得回源去取。
- 淘汰策略:缓存空间有限,满了要删掉一些,常用 LRU(删最久没用的)、LFU(删用得最少的)、FIFO(先进先删)。
- 过期(TTL):给数据设一个有效期,到期就失效。
- 一致性:原始数据改了,缓存里可能还是旧的。所以要有更新或失效的办法,比如写数据库的同时删掉对应缓存。

常见的坑:
- 缓存穿透:总有人查根本不存在的数据,请求每次都打到数据库。
- 缓存击穿:某个热点数据刚好过期,大量请求一下子打到数据库。
- 缓存雪崩:大批缓存同时失效,数据库压力突然暴增。

一句话总结:缓存是用空间换时间,代价是数据可能不是最新的。

想深入了解哪一种,比如 Redis 缓存怎么设计,可以接着问。

#17 我: 解释一下什么是缓存
#18 小克: 缓存就是把常用的数据先放在一个更快、更近的地方，下次要用时直接从这里拿，不用再去慢的源头取。

打个比方：你常查的资料，与其每次跑图书馆，不如复印一份放在桌上，伸手就能拿到。桌上这份就是缓存。

常见的例子:
- CPU 缓存：存放 CPU 最近用过的数据，比读内存快很多
- 浏览器缓存：网页里的图片、脚本先存在本地，再次打开网页更快
- 应用缓存(比如 Redis):数据库查询结果先存在内存里，减轻数据库压力

- 命中/未命中：缓存里有要找的数据叫命中，没有就得回源头取
- 过期和淘汰：缓存空间有限，要定规则清掉旧数据，比如淘汰最久没用过的(LRU)
- 一致性：源头数据改了，缓存可能还是旧的，这是用缓存时最难处理的问题

总结一下：用一点空间换速度，代价是可能拿到旧数据。
