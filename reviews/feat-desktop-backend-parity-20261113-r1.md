## 必修：真实缺陷

### D-01 / High：设置页选模型选的是假目录，保存后新联系人回不了话

位置：`apps/desktop/src/api/wire/settings.ts:12` 的 `toModelSettings`（宿主目录为空时回退到 `INITIAL_MODEL_SETTINGS.models`）；宿主 `DEFAULT_SETTINGS.models` 恒为 `[]`，所以连上后端时这个回退永远生效。本 PR 把 `saveModels` 从未接线守卫里放出来，这条路是本次 diff 打开的。

复现（`model-walk.mjs`，`walk5-model.log`）：

1. 接入 `fengshao1227/deepseek-v4.1-flash`，加联系人小克。
2. 打开设置。「默认说话模型」「默认 Compute 模型」两个下拉的选项是 Claude Opus 5.5、GPT-6.1、Gemini 4、Grok 5、DeepSeek V4 等十个写死的条目，没有一个是网关上的 id；真实在用的模型不在选项里，下拉因此显示第一项「Claude Opus 5.5」，与实际不符。
3. 只改说话模型：保存按钮是灰的，提示「模型目录里没有 fengshao1227/deepseek-v4.1-flash……还有 1 处对不上，修好才能保存」——也就是必须把能用的那个模型也换掉才让保存。
4. 两个都改成 Claude Sonnet 5.5：显示「已保存」。
5. 新加联系人小新，添加页写「说话用全局默认的 Claude Sonnet 5.5」。发一句话，178 秒后只得到「小新 这一轮没回成:上游不可用」，按钮只有重试本轮 / 跳过本轮。没说是模型名不存在，也没有换模型的入口。

网关上实际的 id 是 `fnqtz/claude-sonnet-5-5` 这类带前缀的，`claude-sonnet-5-5` 不存在。结果是：用户在设置里能选的每一项都会让之后的新联系人坏掉，而且回不到原来能用的模型（它不在下拉里），只能去「模型接入」重填一遍。

修复要求：下拉的选项必须来自真实可用的来源（网关目录或用户接入时填的模型），当前生效值必须出现在选项里并正确选中；目录读不到时这块关着并写明原因，不拿演示目录顶上。失败卡要写明是哪个模型、去哪里换。作者在 PR #102 里已在做读取网关目录，但那不在本 PR 内，本 PR 单独合入就是上面的行为。
