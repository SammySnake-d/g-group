### F-01：同进程测试不能验证跨进程单一提交点（AC-21 / R-05）

位置：`packages/adapter-sqlite/src/store.test.ts:108-126`，被测实现 `store.ts:52-63,97-109`。

两个真实子进程在同一文件、同一文档、版本 0 上定点交错，实测：

### RR-01 [P1 / 必修] 子进程启动失败会使测试无界等待；结果后异常退出还能误绿

位置：`packages/adapter-sqlite/src/store.test.ts:123-145,149-155,167-178`，初始化路径 `packages/adapter-sqlite/src/store.ts:41-45`。

**原版自然复现，不依赖错误的产品变异**：单独运行原版“另一进程持有写锁时提交返回 busy”用例，前 3 次成功，第 4 次 B 的 `busyTimeoutMs=0` 在 `openStore` 的 `PRAGMA journal_mode = WAL` 遇到真实 SQLite `database is locked`（扩展错误码 261）并在发 `ready` 前退出。A 已启动并等 `goA`；父进程在 `Promise.all([a.saw("ready"), b.saw("ready")])` 上等待。`saw()` 只在 stdout 看见指定行时 resolve，不监听 spawn error/提前 close，也没有时限，因此不会把 B 的启动失败转成测试失败，也不会释放 A。实验 4 秒后外部有界执行器终止进程组；另一次对只改撤回路径的 R14 副本自然遇到同样情况时，进程在约 78 秒后仍未退出，人工终止，**该次没有记作变异被杀**。进程列表和原始 stderr 已留证。

**独立故障注入**：只在测试夹具中模拟 A 在 `ready` 前退出 42，另一个子进程仍等屏障；用例 4 秒内未结束。另只在子进程打印 `result` 后模拟 A `exit(42)`，用例却返回 **1 通过 / 0 失败**：`proc.done` 丢弃 `close` 的 code/signal，只要解析到 result 就当成功。两个注入都未修改产品实现。

**修复要求**：确保两个连接的初始化不会因为测试用的零 busy 超时互相碰撞；`saw` 必须同时处理 spawn error、非预期 exit/close 和明确超时；`done` 必须校验退出码/信号；所有失败和超时路径都释放屏障并回收本次子进程，不能留下等待进程。补“启动前退出”“输出结果后异常退出”的具名负例，要求有限时间内失败且无子进程遗留；正常用例和 SQLite busy 行为仍绿。

### RR-02 [P1 / 必修] busy 用例用固定睡眠代替进程间完成屏障，可能把正确行为判红

### RR-03 [P1 / 必修] `openStore` 初始化异常时遗留已打开的 SQLite 连接

位置：`packages/adapter-sqlite/src/store.ts:41-49`。`new DatabaseSync(file)` 成功后，`PRAGMA journal_mode`、`SCHEMA` 或后续初始化若抛错，函数直接退出，调用方没有拿到 `SqliteStore`，无法调用 `closeStore`；代码也没有关闭局部 `db`。

独立真实复现：

1. **真实锁超时**：独立进程持有写锁并保持未提交，本进程 `openStore(file, {busyTimeoutMs:0})` 等待约 **10.4 秒**后抛 SQLite `database is locked`（errcode 5）。本进程中目标数据库相关描述符由 0 增至 **4**；显式触发 GC 后降为 0。该路径正是第 7 栏说“超过 10s 未测”的边界。
2. **重复初始化失败**：在临时只读 SQLite 文件上真实尝试 40 次，40 次均因只读错误失败；macOS `lsof` 观察到该文件的打开描述符由 0 增至 **40**，显式 GC 后降为 0。连接不是永久不可回收，但依赖 GC 而非失败时及时释放。
3. **影响对照**：仅在实验子进程把文件描述符上限设为 64；原版连续 55 次初始化失败后，打开另一个健康数据库也报 `unable to open database file`（errcode 14），显式 GC 后才恢复。这个 64 是受控低上限，不是本机默认值。
4. **因果对照**：在隔离副本里只给 `openStore` 初始化异常路径加 `db.close()` 后重抛，40 次失败后的目标描述符为 0；同样低上限下 100 次失败后健康库仍可打开。该对照通过 typecheck 与全仓 47 条测试；本审查没有修改 PR 实现。

**影响**：锁争用、只读或其他初始化错误被上层重试时，未释放的连接可在下一次 GC 之前耗尽进程文件描述符，使无关的正常数据库操作失败。现有 47 条绿和 S01–S20 没覆盖这一错误路径，不能以它们证明连接生命周期安全。
