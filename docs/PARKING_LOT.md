# PARKING_LOT · 暂缓清单

先把当前群协作闭环做到可用，再考虑新增设计。需求里尚未实现的功能也按下面的规则排期。

1. **痛点来源**：真实工作中反复遇到，并有可复核的记录，而不是假想问题。
2. **阻塞程度**：现有手动办法不能合理完成工作，已经影响使用。
3. **依赖前提**：能在现有架构内做一个可独立验证的小改动，不需要先重做底层。

三关全过才列在「可做」，也不自动开工。这里只改排期，不撤销需求、不降低验收标准；**未测不等于未实现，未实现不等于现在必做。** 本次按 `dev/agy-backend` 的 `10d2a78b`、清单实跑及当前进度表核对。

| 任务依赖字段、拓扑排序和写入时查环 | ① 未见前置没做完就被领走；③ 真有问题也先切单一前置条件，不先造全图 | 实跑出现明确前置未完成仍被领走，保留两项的状态和认领时间 |
| 30–50 个联系人／Compute 的 WS 并发与资源压测 | ① 目前是容量问题，不是已量到的拥塞；② 本轮小群链路可用 | 实际群规模接近该范围，或现网测到内存、连接并发、排队时延、丢事件阻塞使用；先量基线，再定改动 |

## 冻结项

| 是什么 | 为什么停 | 什么现象出现再拿出来 |
|---|---|---|
| 写死轮数上限、审查反复打回的上限和熔断 | ① 无反复失控实证；② 现有人工停止和回执覆盖当前需要 | 真任务持续循环、无法自然停；人工停止或既有回执不足 |
| 合入后的语义冲突检测及自动回滚 | ① 未见普通冲突与既有重验之外的反复事故；③ 自动裁决及回滚涉及新规则 | 多次无文本冲突却破坏已验收行为，现有重验不能发现 |
| 按任务费用预算 | ① 未见常规任务成本频繁异常；③ 费用归因与停跑语义未定 | 实际任务反复触发不可接受的花费，已有用量记录可定位 |
| 防 Compute 作弊拦截 | ① 无经核对的反复伪交付；③ 不先搭泛化拦截；既有权限、证据和用户确认照常 | 发言或收据反复与真实执行/工件不符，明确现行核对遗漏 |
| 新增创建额度与跨群公平配额（P2-A2） | ① 缺真实饥饿及排队证据；当前租约／物理停止确认不在冻结范围 | 正常并行任务反复挤掉他人、或确认停止后仍无法分得资源 |
| 外部渠道插件、Outbox、外发与常驻承诺（P2-B1，US4–6/12，AC-35/58 的未交付部分） | ② 本地可手工粘贴授权材料或转送；③ 真实渠道须先做好权限、序列化隔离、回执与失败边界 | 同一批准渠道成为必走流程，手工失败显著；一次只验一个渠道，已有隔离不能撤 |
| 动向摘要与 `/ketchup`（P2-B2，C-US25） | ② 手查聊天、进度与任务面板能继续；未见归来漏办的反复记录 | 真实工作中多次因追未读漏掉待确认事项，手查无法承受 |
| 前端观感重做、DS-Bot 路线（#118） | 当前要的是能打开的版本；③ 重搭 UI 不能作为这轮小改动 | 当前界面出现可复现的操作阻塞，且用户确认对应外观范围 |
