## 2. 已核实事实与严禁夸大的工程边界（采纳 Astra `#681/#684` 纠偏）

| 维度 | 已核实事实（有官方文档或本机只读证据） | 严禁夸大的边界（撤回 `#641` 无实测断言） |

| **Electron 进程模型与同类桌面应用** | • 本机只读核验 `/Applications/Claude.app`（`4.4212.0`）与 `/Applications/mirasim.app`（`0.0.737`）内部均包含 `Electron Framework.framework` 与 `app.asar`，确证为 Electron 应用（本机 `/Applications/Codex.app` 未找到，不作断言）；<br>• 官方 [Process Model](https://www.electronjs.org/docs/latest/tutorial/process-model) 支持 Main 主进程、Renderer 渲染进程与 `UtilityProcess`。 | • **单窗口不等于单 OS 进程**，独立子进程也不自动在应用退出后存活；<br>• **严禁在未实测前承诺“单窗口固定 150–250MB 内存”或“后台 5 个 Compute 零卡顿”**——必须按官方 [Performance](https://www.electronjs.org/docs/latest/tutorial/performance) 在真实负载下做 Profiling，并将 Electron 进程树与 `Claude Code / MCP` 子进程内存分开计量，不靠迁往旁路进程掩盖总开销。 |
| **桌面安全与生命周期合同** | • 官方 [Security](https://www.electronjs.org/docs/latest/tutorial/security) 规范要求渲染进程启用 `contextIsolation`、禁用 `nodeIntegration`、使用最小 `preload` API 并校验 IPC 来源与参数。 | • **调试用的 CDP 端口绝不在正式发行版中长期裸露开放**；<br>• **首版不默认强塞复杂的后台常驻独立 Daemon**：先由用户确认关窗口/退应用时在途任务是暂停、终止还是后台继续，再决定进程存活边界。 |

## 4. 全项目强制执行的 10 条核心工程规则（汇总自 `#553`–`#1124` 定稿）

1. **入口明确、按用户故事串联完整交互链条，且所有需用户确认事项一律发回群聊主消息流（`#758/#772/#916/#925/#930/#967`，对应 `R-16 / AC-34` 与 `meta-development` 第 1 步第 6 条）**：
   - 先有用户故事才有入口（无对应用户故事的孤立入口一律不做；彻底砍掉“全部助手事项未读列表”与“会话全景大盘”）；
   - 引导习惯而非堆砌平铺入口（以群聊/私聊主窗口＋右侧 Split 插件化扩展坞为主舞台；模型配置全软件仅在「全局默认页」与「联系人设置页」两处出现）；
   - 在意图出现处就地给下一步操作（如交付卡片上直接点确认通过或退回修改；**所有需要用户确认的事项一律发回群聊主消息流并 `@` 用户，绝不藏在子会话线程里，`#967`**）；
   - 每个用户故事从意图产生到交付确认端到端连续不断链。
2. **联系人 vs. Compute 严格职责分界、四条开 Compute 判据与途中动态升级（`#796`–`#809/#819`，对应 `AC-33`）**：
   - **联系人直接工具清单收窄**：仅含宿主注册的具名有界工具（效果可知、返回短）与纯方法类 Skill；**通用 shell、任意文件写入、浏览器自动化、执行任意命令的 MCP 与跑脚本的 Skill 严禁进入联系人直接工具清单**；
   - **四条开 Compute 判据（满足任一即开 Compute）**：① 跑任意 shell 命令（哪怕 1 行 `curl`）；② 多轮工具试错；③ 修改工作区；④ 需单独跟踪、中途纠正或验收退回重改；
   - **途中升级**：当场做的事若演变为多步试错，立即停下改开 Compute 并告知用户；
   - **子集继承与凭据句柄**：Compute 不复制联系人私人记忆与 `SOUL.md`（仅收任务说明＋宿主从状态表机械注入的生效群规与硬约束切片），工具权限仅为联系人已授权白名单子集，凭据只传引用句柄绝不传明文。
3. **扫一眼（Attention Loop）唯一消息入口、单人串行单游标与入库端动作去重（`#712`–`#731/#765/#770/#781`，对应 `AC-31`）**：
   - 每位联系人的注意循环是唯一消息处理入口（便宜层只看 `@`、发送人等元数据排时机，绝不读正文判无关丢弃消息，也不做抽样跳过）；
   - 同联系人严格串行（Single-Flight），维护各自独立的单一处理位置 `processed_seq`（绝不在旁观折叠讨论时未处理用户控制指令就盲目推游标）；
   - `ΔState × OutboundActions` 与 `processed_seq` 同事务原子落盘；每个外部动作带唯一 `action_id` 由群消息入库端幂等去重（防“消息已入库、发送方崩溃未记成功”重发）；真正发送前检查 `based_on_seq` 之后有无未处理用户新消息；个人承诺默认只绑定原话所指任务，全部终态且末次汇报发出后由机器自动回收（GC）。
4. **具体模型两处配置、三时机失配拦截（禁止静默换模）与在途快照不可变（`#736/#780`，对应 `R-17 / AC-32`）**：
   - 否决“快/强/审查”抽象档位，只在联系人（说话模型，`pi`）与 Compute（选 Harness＋模型：不填继承全局 / 跟随说话模型 / 单独指定）两处配具体模型；Watchdog 与压缩 Helper 非独立 Agent（压缩复用该联系人说话模型作独立无状态调用）；
   - 在保存、上游改动、启动前三个时机校验模型与 Harness 兼容性，失配立即拦截并给出两条修复路径，**严禁静默退回 Harness 默认模型**；
   - 任务启动写入不可变模型快照，带预览的批量替换工具绝不追溯修改在途与历史快照。
5. **写审分离 ＋ 跨研发厂商独立审查硬门禁（用户 `#553`、`#820`、`#865` 明确拍板定案，对应 `R-01 / AC-26`，修复 `#1103` 累积生产厂商统一）**：
   - 在独立审查门禁（`T5 InReview`）中，宿主代码同时机械强制：① `reviewer_id != author_id`；② **实际执行本次审查的模型原生研发方（`actual_reviewer_model.vendor`）必须不属于本版产物实际参与生成的所有模型原生研发方累积集合（`actual_producer_models[].vendor`：单模型未换模时为单元素集合；半途经失败卡换模重试时累积新旧所有参与生产厂商，`F13`），且所有参与生产厂商与审查厂商均不得为 `unknown`**（与任一参与生产厂商同源或 `unknown` 机械拒绝通过；用户显式手动豁免单独记录为 `豁免 Waived` 而非合规通过；普通日常非门禁审查遇同源提示并标 `同源审查`）。
6. **沉默不等于验收 ＋ 验收退回默认恢复原 Compute 实例（用户 `#583`、`#820`、`#865` 明确拍板定案，对应 `R-09 / AC-28`）**：
   - 交付后进入 `T8a Delivered`，用户不说话超时仅转 `T8 Archived(unverified)` 并标明 `[未人工核验]`，绝不自动算验收通过；
   - 当交付被退回修改（`Reject`）时，**默认优先在原来那个 Compute 实例上恢复（Resume）接着改；若原实例已不可用，则携带 `Handoff Capsule` 交接摘要新开一个 Compute**。
7. **TDD 先红后绿、空实现红基线、双侧标定与把每次纠正编码进结构（`#523/#553/#632`，对应 `R-02`–`R-05 / R-M3 / AC-27`）**：
   - 先写失败的行为测试（留红记录）再写实现；每个测试必须通过空实现红基线（`SG-11`）与阳性埋雷/阴性对照双侧标定；

8. **三类可插拔插件契约（`DataSource / OutboundChannel / UIExtension`）、常驻承诺、职责专注锁（`FocusPolicy`）与五元组作用域预授权外发（`#887/#951/#958/#976/#1068/#1074/#1103`，对应 `US12 / AC-35`）**：
