每张卡写三件事：
- **它是什么**：用户心里会把它当成哪个成熟产品的哪项能力；

每张卡都对上需求文档原文的编号，括号里是用户原话的位置。上一版最大的偏差是把插件系统想窄成了“外部来源”，所以这次每张卡都单写一行“最容易被想窄的地方”。

## 1. 联系人（Contact）
**依据**：U01、U02、U08、§7 概念表、D07.4、AC-01、AC-29（#796–#809、#819）

**是什么**：QQ 好友。区别在于它是一个持久存在的 AI 同事，不是一次对话。它有自己的身份、说话模型、性格（SOUL.md）、长期记忆（MEMORY.md）、记下的承诺、勾选的技能和工具白名单，还有能同时开几个 Compute 的额度。联系人负责听群里的消息、做判断、讨论、派活、汇报、对交付把关。**责任始终在联系人身上**，派了活也不会转给 Compute。

**最容易被想窄的地方**
- 不是“一个会话”或“一个模型”。换模型、重启、换 Compute，都不改变它的身份和记忆（AC-01）。
- 联系人本体能直接用的工具是收窄过的：只有查天气、搜一条资料这类有边界的工具。shell、任意写文件、浏览器自动化都不在里面；要用这些，必须开 Compute。
- 它不懂软件怎么操作，也不该懂。软件操作类工具不进它的上下文，那是 Helper 的事（U05）。

**它由哪几样东西组成**（每样都要能看、能改，#1334）
| 组成 | 是什么 | 依据 |
|---|---|---|
| 职责（给别人看的） | 名片上一个默认职位，每个群另有分工（联系人 × 群）。**被功能读取**：清单认领按分工推荐、@所有人时分工相关的先接、Helper 拉群按分工推荐成员、专职模式拒接分工外的活。改职责只改变谁来接活 | U02、§7、#1373 |
| 预设（给它自己看的工作方式） | 每次干活前放进它的上下文，决定活怎么干。改预设只改变怎么干。不是 Soul（Argon 指南里写成“预设（Soul）”是错位） | U02、D07、#609、#1373 |
| 性格（SOUL.md） | 怎么说话。低频、有依据地改，每次改都留版本，可回滚 | U61、D08.2 |
| 记忆（MEMORY.md） | 做过什么、怎么把活干对。每条带来源消息，可以删、可以纠正 | D08.1、#58 |
| 承诺与定时 | 它答应过的事，带闹钟的就是定时（第 11 张） | U20 |
| 模型与额度 | 说话模型、Compute 配置、同时能开几个 Compute | U08、U68 |

**同一个联系人，两种视角**（落点不同，视角就不同，#1334）
| 从哪进来 | 你想干什么 | 给什么 | 占多大地方 |
|---|---|---|---|
| 聊天里点头像 | 认一下是谁、私信它、@它、看它在这个群干了什么 | **名片**：头像、名字、职责一句话、当前状态，加几个动作（从群聊私信 / 查看对话细节 / 私聊 / @） | 头像旁一个小浮层，不挡聊天 |
| 左侧联系人列表 | 管理这个联系人 | **工作台**：用整个主面板，标签页是 概览 / 职责与预设 / 记忆 / 定时 / 设置 | 主面板全部 |

名片上的“管理”只是跳到工作台，不在浮层里再套一张资料卡。工作台里点“设置”，就在主面板换到设置标签，不弹窗。

**原型里**
- 会话列表的一行，和 QQ 好友一样。
- 头像菜单就是名片（见上表），拍一拍、禁言这些群内动作也在这里。
- 左侧「联系人」里点一个人，主面板换成它的工作台：
  - 概览：在做的事、等你的事、最近做完的（按第 13 张的样式分开）、所在的群；
  - 职责与预设：职责一句话、角色提示词、技能、工具白名单，就地编辑；
  - 记忆：一条一行，带来源，可删、可纠正；性格（SOUL.md）带版本历史，可回滚；
  - 定时：它的全部定时，按群分组；
  - 设置：说话模型、Compute 配置、额度。
- 头像上的状态点：颜色加形状一起区分（第 13 张），不只靠颜色。

## 2. Compute（首版是一个本机会话，后面会长成 Super-agent 的执行层）
**依据**：U08–U12、U21、§1.2 第 60–64 行、D20.4、§8.5 Roadmap、AC-03、AC-07、AC-23、AC-28、AC-30（#796–#809、#820、#1186、#1192、#1284）

**是什么**：联系人为一件具体的活开出去的**执行单元**。它的身份、状态和事件协议都和“在哪跑”无关。
- **现在**：首版就是本机上的一个 Claude Code 或 Codex 会话（`placement: local`）。用户心智上像 Cursor 的 Background Agent，或 Devin 的一个 session。
- **以后**：可以长成 DeepSeek dsh-superagent 那样的两层结构。联系人当 Router，负责对外沟通、维护全局上下文、派活；Compute 当 Worker，在隔离环境里并发干活，只向联系人汇报。运行位置可以换：
  - 像租 GPU 一样租云端的托管机器（`cloud_sandbox`）；
  - 让云端回来用你自己的电脑（BYOM，`byom_daemon`）；
  - 由一个联系人调度多个 Compute，组成集群。
- **计算、会话状态、执行环境三者分开**：换了地方跑，任务、进度、检查点、审查规则都不用改。

满足下面任意一条就开 Compute：要跑 shell 命令；要多轮试错；要改工作区；要单独跟踪或退回重改。

**最容易被想窄的地方**
- **不只是一个 session**（#1284）。session 只是首版的一种实现。设计时要留好“运行位置”这个字段和执行环境适配层，以后接云端时不用推翻状态机。
- **不在群里说话**（AC-03），结果由联系人转述。
- **不继承联系人的记忆和性格**，只拿任务说明和群规切片；凭据只给引用。
- **你能看、能停、能补一句，不能直接和它对话**（U10、U11）。
- 退回重改默认接着原来那个 Compute 做（AC-28）。

**原型里**
- 聊天里只占一行：标题、状态、第几步、耗时。出错时这一行原地变红，后面跟一个「重试」（#1244）。
- 点开在右侧分屏。头部显示**运行位置**，首版写“本机”，点开能看到“云端托管 / 自带机器（即将支持）”，给以后切换留好入口。
- 标签页：过程、改动、预览、检查、检查点。
- 底部只有“补一句”和“顺便问”，没有聊天框。

## 3. Helper（只为你一个人服务的软件助手）
**依据**：U04、U05、U06、§7、evidence/argon-review-125.md 第 3 节、US1（#8、#9、#13、#19、#81、#1251、#1278、#1340、#1353）

**先定本质，再推位置**（#1353）。Helper 由两件事决定：
1. **为谁服务**：只为你。别的联系人 @ 它，它不执行软件操作。
2. **能读哪些内容**：全局打开时默认什么都不读；在某个聊天里叫它，只读这个聊天。

它显示在哪里，不由它是谁决定，而是跟着叫它的地方走：**在哪里叫，就在哪里答。**

**用户心智**：QQ bot。QQ 群里的 bot 就是一个能被 @ 的成员，@ 它，它在群里回一条消息（QQ 机器人官方文档；tencent-connect/openclaw-qqbot 的“仅 @ 时回复”模式）。QQ 群聊的“AI 总结”只给你自己看（腾讯 QQ 官方微博 2025-12-11）。QQ bot 接 dsh 插件后，能列出全部会话、读群和私聊记录、往别的会话代发消息；关键操作先用“允许 / 拒绝”按钮问主人（tencent-connect/dsh-qqbot、dsh-qq-tools）。Helper 就是这套能力只装给你一个人。

**三个入口：在哪叫，就在哪答**
| 入口 | 怎么叫 | 能读什么 | 回答出现在哪 | 谁看得见 |
|---|---|---|---|---|
| **① 聊天里 @Helper** | 输入 @，选人列表第一项是“Helper” | 当前这个聊天 | **这个聊天里的一条消息**，和 QQ bot 一样 | 群里所有人；别的联系人看得见，但不会照着去执行 |
| **② 聊天窗口里的 Helper 面板** | 聊天标题栏的 Helper 按钮，打开后和聊天并排 | 当前这个聊天 | 面板里 | 只有你；不发到群里，适合“有新想法但不想打扰这个群” |
| **③ 全局 ⌘K** | ⌘K，或左侧导航底部的 Helper 图标 | **默认什么都不读**，上下文是空的 | 屏幕中间的命令面板，可以展开成对话 | 只有你 |

**全局 Helper 要读别的聊天或代你发消息时**
- 读：先出一张卡片“要读「前端设计讨论」最近 50 条，可以吗？”，你点了才读。读过的聊天会作为标签列在顶部的“已读取”一栏，点 × 就从它的上下文里移掉。
- 代发：先出一张草稿卡，写明发到哪个聊天、以什么身份发、完整正文，你点“发送”才发。发出去的消息标着“由 Helper 代发”。
- 不确认就不读、不发。

**界面上随时看得出它现在能读什么**
- 面板和全局窗口的顶部都有一行“能读：……”：局部写“当前聊天 · 模型助手群聊”，全局写“没有读取任何聊天”，或列出你允许过的几个。
- 在聊天里 @ 它时，回复下方有一行小字“读了本群最近 30 条”。

**两条用户故事**
- **A（#1278）**：群聊中途你有了新想法，不想打扰当前群，就打开 Helper 面板（②）说：“拉 Claude Code 和 Astra 另开个群聊这个，把刚才那段当背景。”Helper 读得到当前群，给你一张确认卡：新群名、拉谁、带哪几条消息当背景。确认后新群建好，原群里什么都不多；新群第一条系统消息写“来自「模型助手群聊」”。
- **B（US1，#10）**：把功能清单 CSV 拖进 Helper（② 或 ①都行），说“转成这个群的任务”。Helper 先给你预览 N 行，确认后生成本群的共享清单（清单属于群，不属于 Helper），并在群里 @所有人认领。

**边界：所谓“隔离”是什么**（#1251、#1353）
- 隔离的是**工具和上下文**，不是界面。操作软件用的工具（拉群、加联系人、装插件、改设置）只装在 Helper 身上，不进联系人的上下文；联系人看到 Helper 的回复，也不会照着去操作软件。Helper 完全可以出现在消息流里。
- Helper 不是项目成员：不参与“扫一眼”抢活，不认领任务，只在被叫到时才动。
- 敏感或不可逆的操作，一律先出确认卡。
- 后台的资产识别和上下文压缩也算 Helper 体系（U06、#81），但它们没有界面入口。

**最容易想错的地方**
- v1 把它做成盖在聊天上的浮层；v2 又写成“⌘K 侧边栏带当前窗口上下文”，还说“不混入对话流”（Argon #1352）。两次都是**先定了显示方式，再倒推它是什么**。正确的顺序是先定它为谁服务、能读什么，再从入口推出位置。

**原型里**
- ①：@ 选人列表第一项“Helper · 软件助手”。回复是一条消息，头像是 Helper，带“只为你”标签和确认卡；执行结果留一行系统消息。
- ②：聊天标题栏右侧的 Helper 按钮，打开后在聊天右边并排，不盖住聊天。顶部写“能读：当前聊天 · 模型助手群聊”。可以拖文件进来。
- ③：⌘K 打开居中命令面板，顶部写“能读：没有读取任何聊天”。常用指令有：拉群、加联系人、装插件、找某次聊天。要读某个聊天时出授权卡，要代发时出草稿卡。
- 群成员列表里不列 Helper。

## 4. 插件系统（三类插件，挂到群或私聊）
**依据**：U19、U74、US4、US5、US6、US12、D02、D04.2、AC-35、技术栈 §8（#20、#887、#951、#958、#976、#1251）

**是什么**：软件的扩展机制。用户心智上像 VS Code 扩展、Slack App、飞书机器人，或 QQ 的群应用：先在插件中心安装或自己创建插件，再挂到某个群或私聊上，让这个聊天窗口获得新能力。三类插件：
- **数据源（DataSource）**：取外部消息或数据。例如 Telegram 群、飞书群、企业微信、新闻、CVE 订阅。
- **输出渠道（OutboundChannel）**：把结果发出去。例如 Gmail OAuth、SMTP、Resend 发邮件，发 webhook 请求。
- **界面扩展（UIExtension）**：在右侧加一块面板或一个工具。

**定时不是插件**（#1286）。“每天 8 点去看”是联系人自己的能力，见第 11 张卡。插件只回答两个问题：**从哪取数据**（数据源）、**往哪发结果**（输出渠道）。联系人到点醒来以后，调用这两类插件干活。

**最容易被想窄的地方**
- **不是“外部来源的消息”这一个入口**（上一版的错，#1251）。取消息只是数据源插件的一种用法；发邮件、发请求、给联系人提供工具，都是插件。
- 安装、挂到哪个聊天、哪个联系人能调用、能发给谁，是**四道独立的关**（Astra 建议稿 §3）。装了 Gmail 插件，不等于允许给任何人发邮件。停用或撤销以后，旧会话也不能再调用。
- 管理插件（安装、挂载、授权）是软件操作，归 Helper 和你；联系人只是在被授权的范围里**使用**插件。
- 外部数据一律标为“不可信”，不能触发授权（AC-20）。
- 自动外发要预授权：允许发给谁、允许带哪些数据、每小时最多几封都要定死，凭据失效就立即停发（US12 第 5 条）。
- “专职”（只做这件事）和“能用哪些工具”是两件事（FocusPolicy 与白名单分开）。专职的联系人仍然必须响应停止和撤销。

**原型里**
- 左侧导航新增「插件」：插件中心，分已安装 / 可安装 / 创建插件。每个插件显示类型、所需凭据、挂在哪些会话上。
- 群右侧常驻栏有一块「本群插件」：显示挂着的插件、状态，以及要不要“添加插件到本群”。
- 输入框工具栏里，数据源插件的入口变成“从插件取消息”（比如从飞书勾几条）。
- 定时任务的列表里，每条写着它用了哪个插件（比如“取：Telegram 群 → 发：Gmail”）。

## 5. 群规（群公告 / 精华消息）
**依据**：U03、U86、C-US20、C-US26、D02（唤醒前对齐最新群规）、D15 4E R-Rule（#388、#413、#1257、#1618）

**是什么**：QQ 群公告和置顶消息。在 agent 群里，它的本质是**要所有联系人都知道的规则**。人类成员靠眼睛看公告，agent 成员要靠软件把公告注入到上下文里。所以：
- 公告就是群规；
- 精华/置顶消息是补充规则和关键决定；
- 显示给你看的是“已装配”：这条规则的当前版本已经放进这个联系人的上下文。**已装配不等于已遵守**（Astra 建议稿 §1）。是否真的照做，要看它之后的实际输出；有了这样的证据，才标“有行为证据”。
- 新成员进群、联系人重启、定时唤醒，都要拿到当前版本。
- 会话置顶是你自己的导航，和规则无关；“设为精华”的消息如果是一条规则，才进规则视图。
- **这一点不照抄 mirasim**（#1618）：mirasim 的置顶消息只给人看，助手要主动去翻才看得到。我们的群公告由软件装配进这个群里每个联系人的上下文，每次接活都带着；公告改了，下一次接活就按新版本做。

**最容易被想窄的地方**
- 不只是一段展示给人看的文字。改了公告，助手下次接活前就必须按新规则做，定时唤醒前也要先对齐（C-US26）。
- 和协作手册不同：群规是你定的，协作手册是大家磨合出来、经你批准的配合方式。

**原型里**
- 群右侧常驻栏最上方是「群公告」，可以就地编辑、发布，下面显示“3/4 位已装配”，点开能看到每个助手装配的版本，以及有没有行为证据。
- 精华消息紧跟在下面。消息右键可以“设为精华”。
- 右侧栏收起时，聊天顶栏下方常驻一条公告。

## 6. 共享清单（群任务面板）
**依据**：U14、US1、C-US10、AC-30（#10、#24、#1246）

**是什么**：群自带的待办清单，用户心智上像 Claude Desktop 的 todo list，但多人共用。也可以对照 QQ 群待办、Linear 的清单视图。

**最容易被想窄的地方**
- **它是群/软件的能力，不是哪个助手产出的工件**（上一版错把它做成了 Argon 的表格，#1246）。
- 不是表格，也**不是 Compute 状态的镜子**（Astra 建议稿 §3，纠正 #1247 的助手建议）。一行是一件业务任务，状态是：待认领 / 进行中 / 待验收 / 已完成。它下面可以挂零个、一个或几个执行尝试（Compute），尝试的实时状态显示在行内，作为副信息。
- Compute 跑完，任务进入“待验收”，不会自动变成“已完成”；执行者不能替验收者批准。
- Compute 失败了，任务还在，只是这次尝试标红；换人、重试都不会多出一件任务。
- 把认领人移出群，任务留下，回到待认领。
- 认领是带版本号的原子操作：两个人同时领同一项，先到的领到。
- 助手认领或完成一项时，清单自动更新，聊天里只多一行灰字。

**原型里**
- 群顶栏下方常驻一条「清单 3/5」，点开就是群面板里的清单：一行一件事，带认领人头像和任务状态（按第 13 张的样式）；正在跑的 Compute 显示成行尾一个小进度。可以展开看执行尝试。
- 新建清单的方式：手动加，或者让 Helper 导入 CSV。

## 7. 资产与群文件
**依据**：U16、U17、U18、US3、AC-04（#14、#18、#21）

**是什么**：QQ 群文件，再加上一个密码箱。资产包括助手交付的文档和页面、VPS 账号、邮箱、SSH、GitHub PAT 这类可用资源。

**最容易被想窄的地方**
- 资产独立持久化，删聊天记录不会删资产。
- 凭据只把引用交给助手，不给明文。
- 要分清两类：只有 Helper 才能设置的资产（比如凭据），和联系人自己就能产出的资产（比如文档）。
- 资产不等于长期记忆。

**原型里**
- 群右侧栏的「群文件」入口，按类型分组。
- 私聊里发了配置，后台 Helper 会自动存成资产，并插入一行虚线框的系统消息。
- 资产详情里密码不显示明文，并写明哪些助手能用。

## 8. 会话关联与合并转发
**依据**：U24、U25、US2、C-US17、AC-02、AC-20（#17）

**是什么**：QQ 的合并转发，再加一个 QQ 没有的“关联”。默认每个会话的记录互不相通。关联的意思是：这里的助手回答时，可以参考被关联会话的记录。转发的意思是：只把选中的几条交给对方。

**最容易被想窄的地方**
- 关联不等于转发。转发出去的东西里如果有 @，不会触发任何人去做事。
- 取消关联不影响已经转发出去的副本。

**原型里**
- 群右侧栏的「关联会话」：可以添加、取消。关联后标题栏显示「关联 N」。
- 消息右键 → 多选 → 合并转发 → 选会话，对方收到一张转发卡。

## 9. 从群聊私信 / 查看对话细节
**依据**：U46、US10-View、U72、AC-02（#167、#1194、#1235）

**是什么**：QQ 里没有这个。最接近的参照是 Grok Bot：点开灰字查看 bot 之间的原话；以及 Slack 线程的侧栏打开方式。
- **从群聊私信**：只看和这个联系人有关的群消息，加上它平时不刷屏的安排过程。在这里说话，等于在群里 @它，两边是同一份记录。
- **查看对话细节**：看它和你说了什么、和其他助手说了什么、在做什么、记住了什么。

**最容易被想窄的地方**
- 不能直接跳去 1v1 私聊。私聊是另一份隔离的记录。
- 助手之间的讨论属于群记录，但默认折叠成一行。

**原型里**
- 头像菜单的前两项就是这两个入口，打开后在右侧侧边栏显示，返回时逐层退回。

## 10. Watchdog 与上下文压缩
**依据**：U70、§7（#734、#736、#780）

**是什么**：联系人自带的两个机制，不是独立的 Agent，不单独配模型。
- **Watchdog**：定时器加 Compute 的客观信号。发现卡住时生成一个停滞事件，交给联系人判断怎么办。
- **压缩**：用这个联系人自己的说话模型，单独调用一次。

**最容易被想窄的地方**：不要做成单独的联系人或单独的设置项。

**原型里**
- Compute 卡住时，那一行显示“停滞 N 分钟”，联系人会在群里说明原因。
- 不单独设入口。

## 11. 定时（联系人自带的能力）与多视角观测
**依据**：U20、D02、US6、US12、C-US26（#21、#413、#1286）

**是什么**：像真人一样，联系人自己会定时去做事。“每天 8 点去看 Telegram 群并总结”是联系人记下的一条带闹钟的承诺。用户心智上像日历里的一个重复日程，或者 GitHub Actions 里的 schedule。

**边界**
- 定时归联系人，插件只提供数据源和输出渠道（#1286）。
- 到点醒来时，先对齐最新的群规（C-US26）。
- 时区、夏令时和允许的误差，跟着承诺一起存（US12 第 6 条）。

**多视角观测：同一份数据，不同入口过滤和组织方式不同**

| 入口 | 过滤出什么 | 排序 / 分组 | 回答什么问题 | 参考 |
|---|---|---|---|---|
| **群右侧栏 · 本群定时** | 只看本群的定时任务（谁、什么时候、做什么） | 按下次触发时间 | “这个群里谁会在什么时候自动做什么” | Slack 频道的 Workflow 列表 |
| **联系人资料 · 它的定时** | 这个人的全部定时任务，每条标注属于哪个群 | 按群分组，组内按时间排 | “它身上挂了多少事，会不会太忙” | Linear 的 My Issues |
| **左侧「进展 → 定时」总览** | 所有人的全部定时任务 | 时间轴：今天 / 明天 / 本周 / 每周固定，可切换按人或按群分组，可筛选 | “接下来会发生什么、哪些出错了”，不用挨个点头像 | 日历的多日历叠加、GitHub Actions 的 schedule 列表 |

**让信息有序、不分散注意力**（“看绿”，即只有异常才抢眼）：
- 正常的只显示一行灰字：时间、头像、一句话。
- 出错或被跳过才变色。
- 每天、每周固定的折叠成“每天 08:00 ×3”，不一条条刷屏。
- 时间轴上画一条“现在”线，过去的变淡。

**原型里**：上表三处都做，并且能互相跳转。联系人那一处在它的**工作台 · 定时**标签里（第 1 张），不在头像名片里。

## 12. 群模板（复制团队到新项目）
**依据**：US14 第 2 条、AC-38、D08.3（#1160、#1172、#1278）

**是什么**：把磨合好的团队复制到新项目，只带“人和配合方式”，不带“项目内容”。用户心智上像：
- **Notion 复制模板**：先预览，再选包含什么；
- **Slack 复制频道**：带成员和设置，不带消息；
- **Linear 团队模板**：带流程，不带 issue。

**带过去 / 不带过去**（#1172）

| 带过去（可以逐条看、逐条取消） | 不带过去（只列出来让你放心） |
|---|---|
| 成员：每个助手的人设和技能（同一个助手，进新群还是同一个“人”，记忆跟着它自己走） | 全部聊天消息 |
| 群规：群公告、精华消息里的规则 | 文件和资产（包括服务器账号） |
| 配合方式：协作手册里团队通用的条目，每条注明来自哪次对话 | 在做和做完的任务、清单 |
| 团队经验：标为“团队通用 / 到哪都通用”的经验，每条注明来源 | 只对这个项目成立的事实（比如“主题变量在 tokens.css”），默认不带，单独列出来 |

**最容易做错的地方**（上一版被指出“粗糙、选项莫名其妙”）
- 不要出现“scope / project / team / global”这类内部词。改成“这个团队通用”“只在这个项目用”。
- 不要让你对着一堆勾选框猜。按“成员 / 群规 / 配合方式 / 经验”分组，每条用一句话说清，旁边写来源。

**原型里**：分三步，每步一屏。
1. **起名并选成员**：头像卡片，可以去掉某个人。
2. **检查要带走的规则和经验**：分组卡片，每条带来源，默认全选，可以逐条取消；“只在这个项目用”的那组默认收起、不选。
3. **确认**：左边列“会带过去”，右边列“不会带过去”。点“创建新群”后，新群里第一条系统消息写明“从哪个群复制、带了几条”。

## 13. 状态的样子（做完、进行中、等你、出错、正常提示）
**依据**：U75、D09（#1095、#1244、#1286、#1334）

**问题在哪**（#1334 附图）：“做完了，等你验收”“进行中”“最近做完”“正常提示”用的是同一种字号、同一种灰、同一种行高。差别只在一个小圆点和几个字，必须逐字读才分得清。

**为什么会这样**
- **前注意加工**（Treisman 的特征整合理论）：颜色、大小、形状、位置这些特征，人眼不用逐个看就能一眼挑出来。如果所有状态共用同一套特征，就只能靠读字，等于放弃了“一眼看出”。
- **视觉层级**：要你动手的事应该最显眼，做完的事应该退到背景里。现在两者一样重，注意力就被平均分掉了。
- **数据墨水比**（Tufte）：做完的事还画着和进行中一样的完整一行，墨水花在了不需要你行动的信息上。
- **“看绿”**（#1286）：正常就安静，异常才抢眼。

**定下来的样式**（每种状态至少有两个特征和别的不同，不只靠颜色，Astra 建议稿 H22）
| 状态 | 形状 / 图标 | 颜色 | 字重与大小 | 占位 |
|---|---|---|---|---|
| **等你**（要你验收、回答） | 实心圆 + 右侧主按钮“去验收” | 暖橙，带浅底色块 | 标题加粗 | 进“待你处理”和这一行本身；行有底色 |
| **出错** | 三角感叹号 | 红字，左边一道红竖线 | 标题加粗 | 行内原地变红，行尾“重试”；不进输入框上方 |
| **进行中** | 转动的环 + 第几步 / 共几步 | 绿（#1095 用户认可的 mirasim 配色：运行中绿、等待黄、错误红） | 常规 | 正常一行，带细进度条 |
| **做完了**（已验收） | 对勾 | 灰 | 常规、字号小一号 | 收进“最近做完”，默认折叠成一行“今天做完 3 件” |
| **正常提示**（系统行、设置变更） | 无图标，居中 | 最浅的灰 | 小字 | 居中细行，不占气泡 |

**原型里**：Compute 行、清单行、联系人工作台的概览、定时总览，全部用这一套。走查时会截一张“去掉所有文字只留样式”的对照图，验证不看字也能分清。

## 14. 进展：状态卡、完整过程、任务时间线、全景画板与放手档位
**依据**：U79–U84、D21（#1410、#1412、#1426–#1429、#1432、#1443、#1444、#1457、#1461、#1466、#1473、#1474、#1480）

**是什么**：用户把事交给联系人以后，用来建立信任、随时插手的一组视图。它们读的是同一份数据：任务事件记录（谁发起、派给谁、谁续接、什么状态），加上消息锚点和来源标识。
- **状态卡**（聊天里）：取代呼吸灯。一张卡写明它在回哪几条消息、在想还是在写、做了多久；展开看步骤，再往下是「看完整过程 ›」。参照 mirasim 的「正在回复」卡（#1412）。
- **完整过程**：和聊天窗口同一套模板，只有联系人一个人在说话；它派的 Compute 在里面只占一行，点开是 Compute 的过程，也是同一套模板，一层套一层。参照 mirasim 的子会话（#1432）。
- **任务时间线**（群内）：发起 → 派活 → 续接 → 状态，点节点看详情、可以停和退回。参照 mirasim 的主线时间轴（#1457）。
- **全景画板**（跨群）：会话 → 联系人 → Compute 三列连线，顶部是状态统计和筛选，点节点在画板右侧看详情。参照 mirasim 的画板（#1410、#1426），但用弹出遮罩承载，不铺满全屏（#1618）。
- **放手档位**（每个联系人一档）：看过程 / 看里程碑 / 只看结果，决定上面这些默认展开到多细。默认「看过程」，只有你能改（#1480）。

**为什么要分档**：软件的终点是你只验收成品，起点不是。信任靠约束一层层沉淀出来：教训 → 项目规则 → lint 和门禁 → 代码契约（#1473、#1474）。约束越多，你越敢少看一层。验收记录（通过、退回、返工次数）是改档的依据，系统只能建议改档，不能替你改。

**最容易被想窄的地方**
- **两种时间线别混**：任务时间线记的是发生过的事实，内置；「每 100 条消息总结一次」的聊天动向是 LLM 的解读，做插件。插件挂到内置留的时间轴渲染位上，「每 N 条消息」是联系人承诺的一种触发方式（同第 11 张定时），不是插件自己的定时器（#1461、#1480）。
- **一个状态只在一处出现**：状态卡出来以后，头像上的呼吸灯、面板里重复的绿点都删掉（#1391、#1432）。
- **两个入口，同一个视图**：状态卡的「看完整过程」和头像菜单的「看完整过程」打开同一个视图。范围跟着入口走：从群里进入只看本群，从联系人工作台进入看全部，每段标明来自哪个群（#1443）。
- **完整过程只能看**：可以停、可以补一句，不能在里面聊天；想聊去私聊，否则它会长成第三个聊天窗口（#1443）。
- **内置不等于 P0**：P0 只做底座数据（事件记录、锚点、来源标识、待你处理、停滞检测、验收记录，以及档位、教训、消息数触发的预留字段）；这些视图都排 P1。顺序见需求文档 D21.6。

**原型里**
- 消息改成头像和名字在上、内容往下排（#1412）。
- 状态卡样式按第 13 张；「等你」用黄/橙，不用绿（#1418）。
- 全景画板每个节点标来源群或私聊，详情里「打开会话」直达那个聊天。
- **全景画板用弹出遮罩**（用户 #1618 已定）：点背景或 Esc 关闭，因为「进度不是需要时刻打开的」，聊天才是主意图。左侧导航不加「进展」一级页面。再次打开时筛选和滚动位置都还在；详情里「打开会话」关掉遮罩并跳到那个聊天。#1443 的中栏加右栏方案不采用。

## 群/软件的能力 vs 联系人的能力 vs Compute 的工件 vs 插件

| 归属 | 包括 |
|---|---|
| **群/软件能力**（不属于任何一个助手） | 群公告=群规、精华消息、共享清单、群文件/资产空间、成员与身份、禁言、关联会话、工作区与提交记录、临时算力池、协作手册（由大家磨合、你批准）、消息搜索、置顶、免打扰 |
| **联系人能力** | 说话、判断、讨论、认领、派活、汇报、记下承诺、**定时（自带闹钟）**、拍一拍后回应、长期记忆与性格演进 |
| **Compute 的工件** | 代码改动、页面、文档、测试结果、截图、检查点 |
| **插件** | 数据源（取消息/数据）、输出渠道（发邮件/请求）、界面扩展（右侧面板）；挂在群或私聊上。**不含定时** |
| **Helper**（只为你服务的软件助手） | 三个入口：聊天里 @（回复是消息）、聊天窗口里的面板（读当前聊天）、全局 ⌘K（默认什么都不读，读别的聊天和代发前先问你）。负责软件的全部操作、后台资产识别、上下文压缩；不是项目成员，不抢活 |
