# Domain and State Machines

`packages/domain` owns pure identity, authorization, task lifecycle, leases, and ledgers. `packages/kernel` owns orchestration rules and runtime ports for the contact round, Compute, retry, and plugin boundaries. `packages/adapter-sqlite` implements durable storage beneath the server assembly.

Keep I/O outside domain and kernel source. Persist state transitions through their owning stores. Use explicit stable primary keys and `WITHOUT ROWID` for new append-only history tables. Run the state machine and persistence tests when changing transitions or storage and run `npm run check:structure` for the import boundary.

The group checklist projects the existing Task document. A claim compares the revision read by the contact, takes ownership by task ID, and commits the contact's room message in the same transaction. Releasing a running task returns it to the open state after Compute confirms it stopped. Each subsequent claim uses a fresh launch request ID. A room user may reassign a claimed task before Compute starts. Delivery marks ordinary non-workspace tasks completed immediately (clearing `pendingForUser`, closing commitments and open `task-status` cards, and listing them in `duties.doneTasks`), while tasks attached to an unmerged `codeRepo` worktree stay awaiting user confirmation and integration. Both `T8a_Delivered` and `T8_Accepted` tasks with an existing delivery can reopen to `T3_Running` upon user rejection or post-completion chat revision requests.
