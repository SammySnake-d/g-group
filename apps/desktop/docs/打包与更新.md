# 打包、安装与自动更新(macOS)

## 用户怎么装、怎么用

1. 打开 `g-group-<版本>-arm64.dmg`,把 g-group 拖进「应用程序」。
2. 第一次打开:整窗是「接入模型」,填网关地址、令牌、模型,点「保存并连接」。
   - 联系人说话(pi)和 Compute 干活(本机 `claude` 命令)都经这个网关。
   - 页面下方会说本机有没有找到 `claude` 命令;没找到时派给 Compute 的活会失败,装好 Claude Code 后点「重新检测」。
   - 以后在「设置 → 模型接入」里改。
3. 有新版本时右上角弹一条常驻提示:下载 → 显示进度 → 「重启并安装」。设置页「版本与更新」里随时能手动检查。

数据都在 `~/Library/Application Support/g-group/`:`gg-data/`(数据库、Compute 工作目录)、`gg-config.json`(模型网关,权限 600)、`updates/`(下载的新版本)、`logs/updater.log`(更新每一步的记录)。

## 构建与打包

```sh
cd apps/desktop
npm ci && (cd ../.. && npm ci)          # 根目录的 packages/* 会被打进主进程
npm run pack:mac                          # = node scripts/pack-mac.mjs
# 输出在 release/:g-group-<版本>-arm64.dmg、g-group-<版本>-arm64-mac.zip、latest-mac.yml
```

- 渲染层、主进程(含宿主 @g-group/server 和 pi 等依赖)都由 vite 打成单文件,应用里没有 node_modules。
- Compute 的汇报工具(report_progress MCP)单独打成 `dist-electron/report-mcp.cjs`,放在 asar 外,由 `claude` 以子进程拉起,用 Electron 自带的 Node 执行(`ELECTRON_RUN_AS_NODE=1`)。
- dist 已在别处构建好时:`node scripts/pack-mac.mjs --skip-build`;临时改版本号:`GG_VERSION=0.1.1 node scripts/pack-mac.mjs`。
- 只在 macOS 上能打(dmg、签名都要 macOS 工具)。

## 签名

现在用临时签名(`mac.identity: "-"`),没有 Apple 开发者证书:
- 本机自己构建、自己装:能正常打开。
- 从网上下载的 dmg:系统会拦(「无法验证开发者」),要在「系统设置 → 隐私与安全性」里放行一次,或 `xattr -dr com.apple.quarantine /Applications/g-group.app`。
- 应用内更新下载的新版本不带隔离标记,替换后能直接打开。

要发给别人用,需要 Apple Developer Program(每年 99 美元)的 Developer ID 证书 + 公证(notarize)。有了证书以后:改 `electron-builder.yml` 的 `identity` 为证书名、加公证配置,并可把更新换成 electron-updater(发布物格式相同)。

## 自动更新怎么做的

- 发布物:electron-builder 产出的 `latest-mac.yml`(版本、zip 文件名、sha512、大小)+ zip。
- 更新地址默认 `https://github.com/SammySnake-d/g-group/releases/latest/download`(仓库公开,不用令牌);可用环境变量 `GG_UPDATE_FEED` 或设置文件里的 `updateFeed` 改。
- 流程(electron/updater.ts):读 yml → 比版本 → 提示 → 下载 zip 并核对 sha512(不一致丢掉)→ `ditto` 解开,核对解出的版本号、`codesign --verify` → 应用退出后脚本替换 `/Applications/g-group.app` 并重开;替换失败放回旧版。
- 为什么不用 electron-updater:它在 macOS 上走 Squirrel.Mac,要求应用有开发者证书签名;临时签名的应用会被拒。
- 从 dmg 里直接打开(没拖进「应用程序」)时不能替换,会提示先拖进去。

## 发一个新版本

1. 改 `apps/desktop/package.json` 的 `version`(按 x.y.z)。
2. `npm run pack:mac`。
3. 在 GitHub 建 release(tag `desktop-v<版本>`),把 `release/` 里的 dmg、zip、`latest-mac.yml` 三个文件都传上去,发布(不是草稿)。
4. 已安装的应用 10 秒内(启动时)或每 6 小时查一次,看到提示就能更新。

测试更新不对外发布:把 `release/` 当静态目录起一个本地服务(`python3 -m http.server`),用 `GG_UPDATE_FEED=http://127.0.0.1:端口` 打开旧版本。

## 测试与验收用的环境变量

| 变量 | 作用 |
|---|---|
| `GG_USER_DATA_DIR` | 整个应用的数据放到别处(不碰自己那份) |
| `GG_UPDATE_FEED` | 更新地址 |
| `GG_UPDATE_AUTO=off` | 启动时不自动查更新 |
| `GG_BACKEND=server/off` | 开发模式开后端 / 一律不开 |
| `GG_MIND=fake/pi`、`GG_COMPUTE=fake/claude` | 联系人脑子、Compute 用替身还是真的 |
